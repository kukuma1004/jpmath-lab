# 온라인 순위 v3 · 2026-10-27

현재 게임은 프로젝트 `jpmathlab`의 Realtime Database 중 `benchHallV3`를 사용합니다. 선수 보관함의 선수들을 각각 자동 등록하며 `benchHallV2`는 ‘이전 전당’에서 조회합니다. V2 규칙·기록과 그 밖의 운영 분기는 수정하지 않습니다. 익명 Firebase 앱 이름은 기존 `bench-hall-v2`를 유지해 같은 브라우저의 기존 소유권을 보존합니다. 교사·학생 로그인과 연결하지 않습니다.

## 자동 등록과 데이터

프로 시즌 종료·은퇴·저장 불러오기 뒤 요약 기록을 등록합니다. 기본 공개 닉네임은 무작위이며 설정에서 수정·자동 등록 해제가 가능합니다. 공개 닉네임, 아바타, 역할, 커리어 점수, 최고 연봉, 전당 투표율, 최고 OVR, 시즌 수, 1군 요약 성적, 우승·개인상 수, 은퇴 여부와 서버 시각을 보냅니다. 선수 이름·학교·국적·손잡이·원본 ID·전체 저장은 보내지 않습니다.

경로는 `benchHallV3/{batter|pitcher|twoWay}/{anonymousUid}_{careerKey}`입니다. `careerKey`는 선수 ID에서 계산한 16자리 식별자로 같은 브라우저의 여러 선수를 구분합니다. 내보낸 파일에는 공개 설정·인증 정보를 넣지 않습니다. 다른 기기에서 가져온 선수의 기존 공개 기록 소유권은 이전하지 않습니다.

연결이 끊기면 요약만 로컬 대기열에 보관하고 재연결 때 재시도합니다. 선수마다 최소 1분 간격으로 갱신하며 전송 도중 선수를 바꿔도 캡처한 선수의 요약만 보냅니다. 공개 기록을 삭제하면 그 선수의 자동 등록도 중지합니다. 자동 등록만 끄는 경우 이미 공개한 기록은 남습니다.

## 두 순위의 기준

메인 점수는 출전한 1군 시즌만 평가합니다. 고교·대학·2군·공백 시즌은 제외합니다. 과거 저장에서 당시 수비 위치가 없으면 중립 계수를 적용하며 현재 위치로 소급하지 않습니다. 투수 역할이 없으면 당시 세이브·홀드 기록에서 추정합니다.

- 타격: `(안타×2 + 홈런×6 + 타점 + 도루×2 + 볼넷) × 리그 계수 × 수비 위치 계수`를 시즌마다 반올림합니다.
- 투구: `(아웃카운트×0.5 + 탈삼진 + 세이브×6 + 홀드×4 + 승리×5 + 투구 질) × 리그 계수 × 역할 계수`를 시즌마다 반올림합니다. 투구 질은 `max(0, 아웃카운트×0.7 - 자책점×3 - 피안타×0.15 - 볼넷허용×0.3)`입니다.
- 리그: KBO 1, NPB 1.1, MLB 1.25. 수비: C 1.1, SS 1.08, CF 1.05, 2B 1.04, 3B 1.02, RF 1, LF 0.99, 1B 0.97, DH 0.92. 투구: 선발 1, 마무리 1.4, 불펜 1.6.
- MVP·사이영상 100, 신인왕 50, 홈런왕 70, 골든글러브 35, 다른 개인상 25점. 해당 1군 시즌의 프로 우승 35점. 1군 출전 기록이 있으면 `max(0, 최고 OVR−70)×12` 보너스를 한 번 더합니다. 투타겸업 투구 기여는 0.8배입니다. 최종 합계를 반올림합니다.
- 연봉 순위: 완료한 프로 시즌의 연봉 최댓값(만원). 현재 잔고·미출전 계약·이적료와 무관합니다. 유급 재활·2군 시즌 연봉도 포함합니다.

수식은 게임 밸런스이며 실제 WAR·공식 선수 평가가 아닙니다. 기존 전당 투표율 계산은 그대로 남습니다. 순위는 종류별 최대 100개를 조회한 뒤 전체 상위 100개로 합치며 같은 값은 공동 순위입니다.

## V3 규칙 배포와 검수

`career-ranking.rules.fragment.json`은 **부분 규칙**입니다. 전체 규칙으로 직접 덮어쓰지 마세요. 신선한 운영 규칙을 읽고 `rules.benchHallV3`만 추가·수정한 뒤 다른 분기가 동일함을 확인합니다. 이번 배포는 사용자 승인을 받았으며 실제 운영 readback으로 기존 V2와 나머지 규칙 보존을 확인했습니다.

목록 읽기는 `orderBy=score` 또는 `salaryPeak`와 1~100 조회 상한을 요구합니다. 본인 UID·careerKey에만 작성하고 점수 수식·정수 범위·필드 허용 목록·서버 시각·1분 간격·누적 점수/시즌/연봉의 비감소·은퇴 상태를 검사합니다. 본인 삭제를 허용합니다. 전체 커리어를 서버에서 재현하지 않으므로 저장 조작을 완전히 차단하지는 못합니다.

분리된 Auth/Database Emulator 55개 검사와 운영 임시 계정 3개 선수의 15개 검사를 통과했습니다. 운영 검수 기록과 임시 계정은 삭제했고 V2 데이터는 쓰지 않았습니다.

# 이전 온라인 명예의 전당 v2 · 보존된 이력

프로젝트 `jpmathlab`의 싱가포르 Realtime Database 중 `benchHallV2` 경로만 사용합니다. 게임 HTML은 그대로 독립 파일이며, 온라인 화면을 열 때에만 순위를 조회하고 공개 등록을 선택할 때에만 익명 인증과 요약 기록 전송을 시작합니다. 학교·전체 저장·선수 프로필은 전송하지 않습니다.

## 공개할 데이터와 순위

공개 닉네임, 선택 아바타, 포지션, 전당 투표율, 최고 OVR, 시즌 수, 프로·1군 시즌 수, 1군 요약 성적, 우승·개인상 수, 서버 등록 시각입니다. `batter/{anonymousUid}`, `pitcher/{anonymousUid}`, `twoWay/{anonymousUid}`에 브라우저별 최고 기록을 하나씩 보관합니다. 순위는 기존 로컬 전당과 같은 전당 투표율입니다. 동률은 공동 순위로 표시하고 최고 OVR로 표시 순서만 정합니다. 목록은 종류별 최대 100개를 조회하며 전체 화면도 상위 100개만 보여줍니다.

로컬 저장을 제출하는 자율 랭킹입니다. 규칙은 소유권·형식·상한·전당 점수 계산의 일관성·갱신 간격을 검사하지만 전체 플레이의 진위나 저장 파일 조작을 검증하지는 않습니다. 더 강한 경쟁 무결성이 필요하면 시즌을 서버에서 진행하는 별도 모드가 필요합니다.

## 규칙 파일 주의

`ranking.rules.fragment.json`은 **부분 규칙**입니다. 이 파일을 전체 데이터베이스 규칙으로 직접 배포하지 마세요. 현재 운영 규칙을 다시 읽은 뒤 `rules.benchHallV2`만 교체하고, 다른 모든 경로의 값이 동일한지 비교해야 합니다. 기존 경제수학·SEED·학생·계정 경로를 수정하지 않습니다.

- 목록: `orderBy=score`, `limitToLast` 1~100인 읽기만 허용.
- 본인 레코드: 해당 익명 UID만 읽기·작성·삭제 가능.
- 갱신: 더 좋은 기록만, 1분 간격. 삭제는 본인만 가능.
- 임의 필드·다른 포지션·불가능한 범위·계산과 맞지 않는 투표율·클라이언트 작성 시각은 거부.
- 최종 활성화 전에 Database/Auth Emulator에서 확인하고, 운영 규칙 최신본과 다시 비교합니다. 운영 게임 파일과 랭킹 규칙 활성화는 각각 확인합니다.

조회 상한은 [Firebase의 query 기반 규칙](https://firebase.google.com/docs/database/security/rules-conditions)으로 제한하며, 동시 쓰기는 [REST 조건부 요청](https://firebase.google.com/docs/database/rest/save-data#section-conditional-requests)으로 보호합니다.

브라우저 데이터를 지우면 해당 익명 인증의 수정·삭제 권한을 잃을 수 있음을 등록 화면에 안내합니다. 공개 기록 삭제는 로컬 커리어를 삭제하지 않습니다.

## 투타겸업 추가 검수본

기존 단일 포지션 payload는 schema 2를 유지합니다. `twoWay`만 schema 3이며 타격 합계 `statA..D` 외에 `pitchingW`, `pitchingK`, `pitchingSV`, `pitchingOuts`를 보냅니다. 이 필드들은 단일 포지션 경로에서 허용하지 않습니다. 두 역할의 1군 기록만 점수에 포함하고 투구 기여는 0.8배로 더합니다. 공통 최고 OVR·개인상·우승·시즌 점수는 한 번만 계산합니다. 서버 규칙도 같은 수식과 정수 상한을 검증합니다.

규칙 변경은 Database/Auth Emulator 검사를 통과했습니다. 2026-10-24 사용자 추가 배포 승인에 따라 기존 운영 규칙 최신본을 다시 읽고, 기존 `benchHallV2` 분기임을 확인한 다음 이 부분만 갱신해야 합니다. 타자·투수 기록을 삭제하거나 이전하지 않습니다. 다른 운영 분기·문서·인증 설정을 수정하지 않습니다.
