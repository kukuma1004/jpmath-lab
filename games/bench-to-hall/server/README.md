# 온라인 명예의 전당

프로젝트 `jpmathlab`의 싱가포르 Realtime Database 중 `benchHallV2` 경로만 사용합니다. 게임 HTML은 그대로 독립 파일이며, 온라인 화면을 열 때에만 순위를 조회하고 공개 등록을 선택할 때에만 익명 인증과 요약 기록 전송을 시작합니다. 학교·전체 저장·선수 프로필은 전송하지 않습니다.

## 공개할 데이터와 순위

공개 닉네임, 선택 아바타, 포지션, 전당 투표율, 최고 OVR, 시즌 수, 프로·1군 시즌 수, 1군 요약 성적, 우승·개인상 수, 서버 등록 시각입니다. `batter/{anonymousUid}`, `pitcher/{anonymousUid}`에 브라우저별 최고 기록을 하나씩 보관합니다. 순위는 기존 로컬 전당과 같은 전당 투표율입니다. 동률은 공동 순위로 표시하고 최고 OVR로 표시 순서만 정합니다. 목록은 종류별 최대 100개를 조회하며 전체 화면도 상위 100개만 보여줍니다.

로컬 저장을 제출하는 자율 랭킹입니다. 규칙은 소유권·형식·상한·전당 점수 계산의 일관성·갱신 간격을 검사하지만 전체 플레이의 진위나 저장 파일 조작을 검증하지는 않습니다. 더 강한 경쟁 무결성이 필요하면 시즌을 서버에서 진행하는 별도 모드가 필요합니다.

## 규칙 파일 주의

`ranking.rules.fragment.json`은 **부분 규칙**입니다. 이 파일을 전체 데이터베이스 규칙으로 직접 배포하지 마세요. 현재 운영 규칙을 다시 읽은 뒤 `rules.benchHallV2`만 추가하고, 다른 모든 경로의 값이 동일한지 비교해야 합니다. 기존 경제수학·SEED·학생·계정 경로를 수정하지 않습니다.

- 목록: `orderBy=score`, `limitToLast` 1~100인 읽기만 허용.
- 본인 레코드: 해당 익명 UID만 읽기·작성·삭제 가능.
- 갱신: 더 좋은 기록만, 1분 간격. 삭제는 본인만 가능.
- 임의 필드·다른 포지션·불가능한 범위·계산과 맞지 않는 투표율·클라이언트 작성 시각은 거부.
- 최종 활성화 전에 Database/Auth Emulator에서 확인하고, 운영 규칙 최신본과 다시 비교합니다. 운영 게임 파일과 랭킹 규칙 활성화는 각각 확인합니다.

조회 상한은 [Firebase의 query 기반 규칙](https://firebase.google.com/docs/database/security/rules-conditions)으로 제한하며, 동시 쓰기는 [REST 조건부 요청](https://firebase.google.com/docs/database/rest/save-data#section-conditional-requests)으로 보호합니다.

브라우저 데이터를 지우면 해당 익명 인증의 수정·삭제 권한을 잃을 수 있음을 등록 화면에 안내합니다. 공개 기록 삭제는 로컬 커리어를 삭제하지 않습니다.
