# R11 표시·계약 기록 보완

R10 배포 빌드를 기준으로 1~6 순서대로 확인한 R11.0 변경 내용입니다. 2026-10-30 사용자의 배포 승인 범위이며, 배포 성공 여부는 Pages 완료 상태와 공개 파일·브라우저 확인으로 별도 검증합니다.

1. 일반 숫자에는 최대 소수점 1자리의 표시 함수를 사용합니다. 예를 들어 `28.700000000000003`은 `28.7`로 보입니다. 내부 값과 저장은 그대로입니다. 야구 기록 자릿수 질문에 답변이 오기 전에는 타율·출루율·장타율·OPS·수비율은 3자리, ERA·WHIP는 2자리를 유지합니다. 표시 정밀도는 `DATA.displayPrecision`에서 분리했습니다. 화면의 성장 미리보기와 실제 정수 능력 변화도 구분합니다.
2. `4.1억원`과 `4억 700만원`은 저장 금액이 달라진 것이 아니라 서로 다른 표시 함수 때문이었습니다. 공통 금액 표시로 통일해 원본 `40700`만원은 모든 새 화면에서 `4억 700만원`, `38100`만원은 `3억 8,100만원`으로 표시합니다. 계약 적용·연봉 지급 계산은 바꾸지 않았습니다. 과거 저장 문구는 그대로 두고, 실제 저장 금액을 확인할 수 있는 경우에만 표시 금액을 보정합니다.
3. 승인 상태만으로 체결 방식을 판단하던 부분을 수정했습니다. 희망액 합의와 구단 제시액 수락은 별도로 저장하며 FA·포스팅·KBO 복귀·트레이드도 실제 경로를 기록합니다. 새 계약/계약 로그의 선택적 `agreement`와 불변 `contract` 스냅샷으로 기록실·은퇴북이 같은 정보를 씁니다. 이전 형식은 계속 읽고, 진행 중인 예전 협상은 명확한 메시지가 있을 때만 방식을 인식합니다. 방식 정보가 없는 과거 확정 계약은 추측해 원문을 바꾸지 않습니다.
4. 모든 현재 피로 표시는 `player.health.wear`를 사용합니다. 부상 판정 근거의 `wearBefore/After`는 판정 당시 스냅샷으로 구분합니다. 예를 들어 판정 후 5.5에 대표팀 참가 7이 더해진 현재 값 12.5를 헤더에서 13으로 반올림하던 혼동을 없앴습니다. 현재 피로로 과거 부상 확률을 재계산하지 않습니다.
5. 기존 메달 특례 구현은 정상입니다. 미필 한국 선수의 아시안게임 금메달과 올림픽 금·은·동메달은 특례를 적용하고 입대 계획을 해제합니다. 이후 상무/현역 지원과 강제 복무가 차단되며 병역 탭·선수 상태에 특례가 표시됩니다. 아시안게임 은·동, WBC·프리미어12·청소년 대회는 특례를 주지 않고 이미 복무 완료한 기록은 유지합니다. 규칙·확률 변경 없이 실제 시즌 파이프라인으로 검증했습니다.
6. 기존 하단 탭바는 선수 생성 후 너비 1023px 이하에서 `커리어 / 시즌 / 관리 / 이적 / 기록`으로 고정 표시됩니다. 1024px 이상에서는 숨기고 사이드바를 유지합니다. 캐릭터 생성 중에는 선수용 탭바가 없습니다. 320~1280px의 11개 너비와 경계값에서 검증했으며 레이아웃 규칙은 바꾸지 않았습니다.

검수는 격리된 로컬 Chrome과 가상 저장으로 수행했습니다. 운영 저장·온라인 순위에 테스트 기록을 쓰지 않았습니다. v1~v5 호환, 진행 중 시즌 보존, 계약금/연봉/RNG, 36개 커리어 950시즌의 수치·확률 및 R10 명예의 전당 평가가 동일한지 대조했습니다. 실제 휴대전화 기기는 검사하지 않았습니다.

재실행 가능한 기본 회귀 테스트: 저장소 루트에서 `node --test tests/bench-to-hall-display.test.cjs`. 소수 노이즈·정확한 금액·일반/FA의 두 체결 경로·선택적 필드 왕복·과거 협상 근거 처리를 검사합니다. 추가 검수 기록은 로컬 `.dream-loop/display-v11/`에 있습니다.
