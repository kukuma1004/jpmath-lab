# 3D BILLIARDS · Phase 1 검증 기록

현재는 **캐롬 자유 연습을 실행할 수 있는 로컬 검증판**입니다. 제이피매쓰랩의 `games/billiards/`에 추가했고, 게임룸의 새 카드에서 진입합니다. 기존 작업 폴더에 동시 수정이 많아 최신 `origin/main`의 `9864b26`에서 `codex/billiards-phase1-20261120` 브랜치를 별도 작업 폴더에 만들었습니다. 공개 배포는 수행하지 않았습니다.

## 실행과 구현 범위

- 로컬 정적 서버: <http://127.0.0.1:5190/games/billiards/>. 저장소 루트에서 `python -m http.server 5190 --bind 127.0.0.1`.
- 2.84 × 1.42 m 캐롬 테이블, 반지름 30.75 mm·질량 0.21 kg의 3/4공 연습 배치.
- 드래그/미세 조준, 큐 스트로크, 당점·파워, 흰/노란 수구, 탑뷰/큐 시점·확대/회전·자동 전환 옵션.
- 정면 충돌/쿠션/밀어치기·끌어치기/기본·3공 연습 배치, 기본·고급 보조, 실제 물리 Worker의 최대 10초 예측.
- 공이 모두 정지해야 다시 샷 가능. 일시정지, 같은 초기 상태·입력을 사용하는 이전 샷 재생, 접촉 시간 순서 기록. 모바일 기록 창·접기 패널·세로 파워.
- 절차적 월넛/브라스/천/공/큐, 한 개의 그림자 조명, 합성 충돌음, 소리·그래픽·모션·카메라 로컬 설정.
- 소스는 `source/`, 번들은 `index.html`+`assets/`. 자기 게임 설정 키 외의 저장 데이터나 학생 데이터에는 접근하지 않습니다.

## 자동 검증

`npm run build`의 타입 검사와 Vite 빌드가 통과했습니다. Three.js 분리 번들은 약 541 kB/압축 138 kB이고 Vite의 500 kB 경고가 남습니다. 런타임에 CDN이나 원격 에셋을 가져오지 않습니다. 빌드 단계는 전용 `source/dist/`에서 성공한 파일만 게임 경로로 복사하고, 자신의 오래된 해시 번들만 정리합니다.

`npm test`: **26개 통과**. 정면 반발계수·운동량, 비스듬한 탄성 충돌, 100 m/s swept 충돌, 동시 코너·밀집 다중 충돌, 임의 회전 충돌의 수동 에너지 감소, 16공 접촉 랙, 5/7 구름 전환, 구름 마찰, 타격 토크, 실제 충돌 후 밀기/끌기 방향, 쿠션의 좌우 회전, 수직축 회전의 임의 휨 금지, 순수 회전 정지, 저속 정지, 잘못된 입력, 복제 결정성, 배치 유효성, 24개 시드 샷의 겹침·에너지·유한성, 중복 입력·일시정지·정확한 재생·기록 분리·진행 중 초기화를 검증했습니다. 충돌 검사에는 무작위 공 충돌 800개와 쿠션 충돌 800개가 포함됩니다. 안전 정지 개입은 이 검증에서 0회였습니다.

`npm run test:browser`: **27개 통과**, [원자료](browser-pass-1/result.json). 실제 마우스/키보드·터치 이벤트로 조준, 당점, 파워, 카메라, 샷, 정지, 중복 입력, pause, replay, 설정 저장, 기록 창, 모바일 접기와 화면 회전을 확인했습니다. 브라우저/콘솔/HTTP 오류는 0개였습니다.

`node scripts/final-capture.mjs`: **11개 통과**, [모션·배치 원자료](final-motion.json). 최종 렌더링을 사용한 큐 준비→스핀 샷의 연속 프레임/비디오와 390×844, 360×740, 768×1024, 844×390, 1366×768에서 샷 버튼의 화면 내 배치, 게임룸 카드·커버·진입을 확인했습니다. 화면 밖에 있던 가로 화면 샷 버튼을 수정한 뒤 재검증했습니다. 모션 비디오는 원자료의 `video` 경로에 로컬 보존하며 공개 소스에서 제외합니다. 관찰한 큐 준비·타격과 물리 이벤트의 순서가 일치하고 공의 쿼터니언이 연속으로 변했습니다. 마지막 크기 관찰 수정은 다음 별도 회귀 검사와 캡처로 확인했습니다.

`node scripts/resize-smoke.mjs`: **10개 통과**. 타이틀/시작/처음 화면 복귀/화면 회전 시 캔버스의 CSS 크기와 렌더러 크기 일치, 새 배치의 자동 조준 카메라, 반복 조준의 지오메트리 증가 여부, 가로 화면 샷 버튼, 일반 진입점의 QA 훅 비노출을 별도 확인했습니다. [결과와 최종 번들 SHA-256](resize-smoke.json). `git diff --check`도 통과했으며, 생성한 번들은 Git 속성으로 바이트를 보존합니다.

`npm run inspect:canvas`: 선언한 5개 상태 모두 통과. `check_evidence.py`도 현재 run ID **billiards-phase1-final-4**의 9개 필수 산출물을 확인했습니다. 시각 회귀 보호를 위해 명시적 상태 설정·시뮬레이션 정지 훅, viewport별 실제 이미지와 픽셀/리소스 보고서를 보관합니다. 이전 패스의 렌더 크기 오류는 진단 자료로만 남겼습니다. 자동 이미지 diff 기준선은 아직 확정하지 않았습니다.

**중요한 성능 경계:** 자동화 브라우저는 SwiftShader 소프트웨어 렌더러를 사용했습니다. 이 환경의 FPS는 실제 하드웨어 성능 자료로 사용할 수 없습니다. 60FPS 목표, 물리 휴대폰의 발열·배터리·터치와 장시간 메모리 안정성은 아직 확인하지 않았습니다. 반복 조준의 리소스 재사용과 시뮬레이션 안정성만 확인했습니다.

## 시각 평가

스킬의 1/2/3 앵커를 확인하고, 당구 장르의 역할로 평가했습니다. 신규 게임이므로 이전 점수는 없습니다. 다음 평가는 최종 PC·모바일 진행 및 큐 시점 전체를 기준으로 한 내부 평가이며 사진 수준의 실제 당구장 재현을 뜻하지 않습니다.

## 후속 단계와 미구현

3구·4구의 점수/파울/턴/이닝/승리, WPA 8볼/포켓/볼 인 핸드/콜샷, 2인 경기와 AI 난이도는 아직 없습니다. 경쟁 모드 대신 자유 연습이라는 상태를 게임과 게임룸에 표시합니다. `RuleEngine` 계약과 독립 테이블 설정·샷 입력/복제를 다음 단계에서 사용할 수 있습니다.

물리는 **평면·구면 점접촉 강체 모델과 일정 초기 계수**입니다. 고정 스텝 내 마찰과 충돌을 분할 계산하므로 마찰이 있는 정확한 연속 시간과 차이가 생깁니다. 실제 장비·고속 촬영과의 계수 보정/오차 검증, 높이가 있는 쿠션 nose의 변형·탄성 모델, 점프·마세·스쿼트·미스큐는 미구현입니다. [모델 수식·근거·한계](physics-model.md)를 확인하세요.

다음 작업은 Phase 2 국내식 4구 규칙 프로필과 처음부터 끝까지 진행하는 2인 경기입니다. 물리 보정의 검증 자료는 경기 규칙 테스트와 구분해서 추가해야 합니다.
