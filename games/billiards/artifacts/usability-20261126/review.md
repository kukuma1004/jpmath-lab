# 드림루프 · 당구 조작 검수 (2026-11-26)

판정: 두 번 누르는 왕복 게이지 자체는 단순하지만, 기존 모바일 조작은 개선이 필요했다. 실제 브라우저 입력에서 핀치 확대가 조준을 바꾸고, 게이지 시작 후 샷 버튼이 움직였으며, 미세 조준이 접힌 패널 안에 있었다. 같은 게임 화면을 입력으로 생성한 목표 화면과 세 차례 비교하고 조작을 수정했다. 실제 이용자 대상 사용성 연구나 실물 휴대폰 검증은 아니다.

## 비교와 변경

| 조작 | 기존 관찰 | 현재 결과 |
|---|---|---|
| 같은 자리 두 번 누르기 | 취소 버튼 등장으로 샷 버튼 y가 724.59→699px 이동 | y=724.53px로 고정, 동일 좌표 터치 두 번으로 실제 타격 |
| 두 손가락 확대 | 손을 차례로 떼고 남은 손가락을 움직이면 조준각도 변경 | 손가락을 전부 뗄 때까지 확대 제스처로 유지, 조준/배치 입력 억제 |
| 미세 조준 | 세부 패널을 먼저 펼쳐야 하며 높이28px | 기본 화면의 44×44px ±, 한 단계0.5도, 시점·확대율 유지 |
| 모바일 글자 | 선수 정보가 줄바꿈되며 상태 줄과 가까워짐 | 이름/점수와 수구/기록을 두 줄로 분리, 넘치는 보조 기록은 말줄임 |
| 가로 8볼 | 콜샷+미세 조준이 함께 열리면 샷이 화면 아래로 밀림 | 짧은 가로 화면에서 콜/파워 영역을 압축, 샷 버튼 화면 안 유지 |
| 터치 안내 | 모바일에도 ‘휠로 확대’ | ‘두 손가락으로 확대’, 도움말도 새 기본 ± 배치에 맞춤 |

기본 샷 방식, 물리/규칙/AI와 저장 키는 그대로다. 자동 카메라는 드래그 조준 때 활용하고, ±/방향키의 작은 수정은 선택한 카메라를 유지한다.

## 드림루프 과정

- 공개 현행 화면을 PC1440×900, 세로390×844/360×740와 가로844×390에서 캡처했다.
- built-in image_gen에 기존 모바일 화면을 편집 대상으로 전달했다. 청색 천·월넛·브라스·점수판과 두 번 샷을 보존하면서, 기본 미세 조준·고정된 큰 샷 버튼·접힌 당점·분리된 보조 동작을 요청했다. 새 테이블/캐릭터/외부 에셋은 요청하지 않았다.
- 생성 결과는 로컬 `games/billiards/.dream-loop/target.png`, 기준 화면과 중간 결과는 `.dream-loop/usability/`에 보존하고 Git에서 제외했다. 원본 생성 파일은 Codex generated_images에도 남아 있다. 서비스에서 생성 그림을 실제 플레이로 제시하지 않는다.
- 1차: 기본 ±, 취소 분리, 핀치의 조준 혼입 차단. 검사에서 ± 높이40px를 발견했다.
- 2차: ±44px, 미세 조준의 카메라 보존, 터치 안내/시점 조작 가독성.
- 3차: 모바일 점수판/간격. 이후 회귀 검사에서 발견한 가로 8볼 밀림은 추가 시각 라운드가 아닌 결함 수정으로 해결했다.
- 목표와의 일치는 시각·조작 구조로 비교했다. 픽셀 완전 일치 점수나 실제 사용자의 편의성 점수를 만들어 보고하지 않는다.

## 확인한 근거

- [기존 실제 입력](baseline.json): 조준 혼입, 기본 ± 미노출/목표 크기, 샷 위치 이동의 실패4개를 보존했다. 새 요구를 정의한 비교 검사이며 기존 게임 전체가 작동하지 않았다는 의미는 아니다.
- [현재 실제 입력](controls.json): **32개 통과**, 실패/페이지·콘솔 오류0. 핀치/취소 복구, 기본 ±와44px, 물리 샷 입력, 카메라 유지, 같은 자리 두 번 타격, 취소, AI·운동 중 입력 제한, 8볼 콜·볼 인 핸드, 작은 화면·회전·패널 확장.
- `npm test`: **10파일120개 통과**. 물리·규칙·AI·실제 경기 테스트. 이번 수정에서 해당 핵심 모듈의 코드는 변경하지 않았다. 재실행으로 생긴 경기 원자료 차이는 elapsedMs뿐임을 확인해 타이밍만 바뀐 원자료는 복구했다.
- `npm run build`: 타입 검사·프로덕션 번들 통과. 기존 Three.js의500kB 안내는 그대로다.
- [경기 UI 회귀](regression.json): **41개 통과**, 오류/서버 쓰기0. 4구/3쿠션/8볼의 실제 마지막 샷 승패/재생, AI, 저장, UI·터치와 화면 크기를 재검증했다. 최초 실패의 가로8볼 조합은 수정 후 다시 실행했다. 최종 결과의 checks/errors가 기준이다.
- [캔버스 manifest](evidence.json): 새 runId로 PC/모바일 이동·게이지·큐/포켓6상태의 실제 비어 있지 않은 캔버스와 예산을 검증했다. 렌더러는 AMD Radeon780M D3D11. 이 검사는 사람의 조작 만족도나 실제 휴대폰 성능의 증명이 아니다.

## 재현

저장소 정적 서버를5196에서 실행하고 source에서 `node scripts/usability-browser.mjs`를 실행한다. `BILLIARDS_URL`과 `BILLIARDS_EVIDENCE`로 공개 URL/출력 경로를 지정할 수 있다. 기존 검사는 `node scripts/complete-browser.mjs`. 캔버스는 `node scripts/inspect-threejs-canvas.mjs --manifest ../artifacts/usability-20261126/evidence.json --url http://127.0.0.1:5196/games/billiards/?qa=1`.

배포 시 현재 공개본의 해시 자산을 retained-assets.json에 추가해 캐시된 예전 HTML도 계속 열리게 한다. 최신 원격의 다른 게임/학생 자료는 보존한다. 최종 커밋의 Pages·공개 해시/실제 조작 수신증은 커밋 자기참조를 피하기 위해 로컬 `.dream-loop/usability/public/`에 기록한다.
