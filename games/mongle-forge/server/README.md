# 몽글 대장간 시즌 1 · 무기 랭킹

사용자 요청에 따라 시즌 `season-20261120-1`은 나무검 +0, 별철 10,000개, 효과 하나로 시작합니다. 이전 몽글 대장간 저장과 백업만 초기화합니다. 시즌 저장 키를 분리해 이전 버전의 열린 탭이 새 진행도를 덮어쓰지 못하게 했습니다. 초기화는 한 번이며 이번 시즌의 강화·최고 단계·재료·효과·실패 보정·이력은 재접속 후 유지됩니다.

온라인 무기 기록은 프로젝트 `jpmathlab`의 Realtime Database 중 `mongleForgeV1/season-20261120-1/{anonymousUid}`만 사용합니다. 별도 Firebase 앱 `mongle-forge-ranking-v1`에서 익명 인증하며 기존 학생·교사·다른 게임의 로그인과 연결하지 않습니다. 목록은 상위 100개만 조회합니다. 첫 강화·특수 강화·판매에서 최고 무기를 보관하고 자동 등록하며, 임의 닉네임은 화면에 표시하고 변경·자동 등록 해제를 제공합니다.

공개 필드는 대장장이 닉네임, 무기 이름, 강화 단계, 특수효과 1~3개, 감정가, 서버 등록 시각입니다. 원본 저장·재료·학생 정보는 전송하지 않습니다. 브라우저당 최고 감정가의 무기 한 개를 보관하고, 같은 감정가에서는 기존 무기의 이름을 수정할 수 있습니다. 등록 당시 기록은 원래 무기가 파괴되어도 보관됩니다. 본인만 수정·삭제할 수 있고 조건부 요청으로 동시 등록 충돌을 처리합니다.

보호권 사용량 `protectionUses`도 선택 필드로 공개합니다. 해당 무기 기록을 세울 때까지 누적 사용한 수를 0 또는 양의 정수 문자열로 저장합니다. 같은 무기를 보호권으로 유지했을 때 감정가가 그대로여도 사용량을 갱신하며, 그 뒤 낮은 무기에서 쓴 보호권을 과거 최고 기록에 붙이지 않습니다. 같은 기록에서는 사용량 감소·삭제를 거부합니다. 예전 정보가 없는 기록은 ‘미기록’으로 표시하고 임의로 0을 채우지 않습니다. 현재 보유 중인 최고 무기와 일치하는 로컬 기록에는 확인 가능한 누적 사용량을 반영해 자동 갱신합니다.

감정가는 512자리 0 채움 문자열로 저장하여 JavaScript 정밀도 범위를 넘어도 정렬을 유지합니다. 강화 단계는 128자리 문자열까지 등록합니다. 이 표시 범위를 넘는 무기도 게임에서는 계속 강화할 수 있습니다. 감정가 동점은 Firebase 조회와 동일한 UID 내림차순으로 고정하여 상위 10명을 정합니다. 브라우저 저장을 제출하는 자율 랭킹으로 전체 플레이의 진위는 서버에서 재현하지 않습니다.

## 보호권·판매·생산 보너스

현재 시즌 진행은 `:storage-1` 저장 키로 한 번 옮깁니다. 직전 `:risk-1`, `:rainbow-1`, `:market-1` 키와 이전 시즌 키의 강화 단계·재료·효과·실패 보정·보호권·기록을 유지하면서 오래 열린 탭이 중복 효과를 제거하거나 새 데이터를 덮어쓰지 못하게 합니다. 새 저장에 성공한 뒤에만 이전 키를 정리합니다.

보호권은 도전 단계별 한 장씩 보유할 수 있으며 원가는 `1000 + 목표단계²×100 + 일반 강화 원가×8` 별철입니다. 성공하면 남겨두고 실패할 때만 사용합니다. 현재 +99 이하에서는 실패 결과를 현재 단계·효과 유지로 전환합니다. 현재 +100 이상에서는 보호권을 써도 1강 하락하지만 효과 유지·파괴 방지는 적용합니다(+100에서 +101 도전 실패 시 +99). 성공 시 권을 보관하고 실패 시 목표 단계 권 1장만 소모합니다. 일반 실패 보정은 도전한 목표 단계에만 적용하며 최고 기록은 보관합니다. 보호 발동 이력에 실제 도착 단계 `to`를 저장해 이전 규칙의 단계 유지 이력을 소급 변경하지 않습니다. 보호 발동 횟수를 별도로 누적하고 기존 저장은 남아 있는 보호 발동 이력에서 시작합니다. 판매는 감정가의 10%를 정수 내림하여 지급하고 검과 효과를 제거합니다. 제작비를 내고 새 검을 만들며 보호권과 최고 등록 기록은 보관합니다. 판매 확인에는 무기 세대·단계·효과를 대조하여 다른 탭이 바꾼 검을 잘못 판매하지 않습니다.

제련은 기본 4/초, 직전 버전에서 최고 강화로 늘어난 생산량의 두 배, 현재 강화 단계²÷2(내림)를 합합니다. 검이 파괴되거나 판매되면 현재 강화 보너스만 사라집니다. 본인 Firebase UID를 확인하고 공용 순위표에서 1~10위에만 초당 `100,95,90,85,80,75,70,65,60,55` 별철을 더합니다. 30초마다 조회하며 검증 유효 기간은 60초입니다. 조회 실패·유효 기간 종료 시 보너스를 중단하고, 새 순위를 과거 미수령 시간에 소급 적용하지 않습니다. 기본 제련의 최대 8시간 오프라인 수령은 유지합니다.

자동 등록할 최고 무기 요약은 파괴·판매 전 상태와 같은 저장 트랜잭션에 보관하고 성공 후 갱신합니다. 연결이 없으면 재접속·온라인 복귀 때 재전송합니다. 공개 기록 삭제는 자동 등록도 끄며 보관 요약을 임의로 다시 게시하지 않습니다. 서버 데이터 형식·보안 규칙은 기존 경로 그대로 사용합니다.

## 특수효과 리롤

효과는 잿불(빨강), 노을(주황), 별빛(노랑), 숲(초록), 서리(파랑), 폭풍(남색), 월식(보라)의 7종입니다. 슬롯은 세 개이며 같은 효과를 세 번 붙일 수 있고 배율도 세 번 곱합니다. 추가 효과는 모든 7종에서 가중치로 뽑습니다. 세 개가 모이면 특수 강화 버튼이 리롤로 바뀝니다. 세 슬롯 중 하나를 균등 확률로 고르고 그 슬롯의 이전 효과만 제외한 6종에서 새 효과를 뽑습니다. 다른 두 슬롯과 중복될 수 있습니다. 강화 단계·나머지 두 효과·보호권·일반 실패 보정은 유지합니다. 특수 강화 기본 원가는 `100 + 10×(현재 단계+1)²` 별철이며 두 번째 효과는 기본값, 세 번째는 2배, 리롤은 3배입니다. 최고 기록·과거 생산 업그레이드는 가격에 영향을 주지 않습니다. +32 기준 10,990 / 21,980 / 32,970 별철이며 할인 시간에는 각각 절반입니다. 추가 성공률 60% / 30%는 유지하고 리롤 교체는 확정입니다. 감정가는 내려갈 수도 있습니다.

리롤 전후 최고 감정가를 자동 등록 보관함에 반영합니다. 낮아진 현재 무기의 판매액은 실제 현재 감정가의 10%이며, 등록된 최고 기록은 유지합니다. 변환 슬롯·교체 전후 효과·감정가는 이력과 저장에 남습니다. 버튼을 누를 때의 무기와 가격 조건을 대조하여 다른 탭이 바꾼 검에 이전 리롤을 적용하지 않습니다.

감정가의 기본값은 이전 다항식 `120+15L(L+1)(L+2)`에 `(10+L)/10` 강화 보정을 곱해 내림한 값입니다. 여기에 세 효과의 배율을 곱합니다. 예전 보관 기록도 같은 단계·효과로 재감정하며 자동 등록이 더 높은 감정가로 갱신합니다.

## 한국시간 해피타임

매일 한국시간 07:00~08:00, 12:00~14:00, 21:00~24:00에 일반 강화·재제작·보호권·특수 강화·리롤 지출을 50% 할인합니다. 종료 시각은 제외하며 소수점은 올림합니다. 보호권 원가에 이미 할인된 강화비를 다시 넣지 않고 최종 원가를 한 번만 할인합니다. 판매 수입은 할인하지 않습니다. 표시된 견적과 실제 지불 시각의 비용 조건이 바뀌면 지출을 거부하고 새 가격을 보여줍니다. 한국시간은 기기 표기 시간대와 독립적으로 UTC+9로 계산합니다.

`ranking.rules.fragment.json`은 부분 규칙입니다. 신선한 운영 규칙을 읽어 `rules.mongleForgeV1`만 추가하고 다른 모든 분기의 해시가 같은지 배포 전·후 비교합니다. 이 파일을 전체 운영 규칙으로 덮어쓰지 않습니다. 공개 조회 상한, 익명 UID 소유권, 닉네임과 무기 이름, 정수 문자열, 효과의 중복·빈 슬롯 순서, 필드 허용 목록과 서버 시각을 검사합니다.

Firebase의 [조회 조건](https://firebase.google.com/docs/database/security/rules-conditions), [조건부 쓰기](https://firebase.google.com/docs/database/rest/save-data#section-conditional-requests), [규칙 REST 배포](https://firebase.google.com/docs/database/rest/app-management)를 따릅니다. Emulator와 운영 검수의 임시 등록 기록 및 익명 계정은 검수 후 삭제합니다.

## 운영자 단일 무기 수정

`mongleForgeV1/adminGrants/{uid}`는 인증된 본인만 읽고 클라이언트는 쓸 수 없습니다. 운영자가 지정한 시즌·수정 ID·원본 무기 요약·효과 3개·발급 시각을 검증하여 한 번 적용합니다. 이미 파괴·판매한 무기는 살리지 않으며, 발급 후 플레이한 새 무기에는 적용하지 않습니다. 원본과 맞는 기존 보유 무기 및 최고 기록만 반영하고 로컬 저장에 수정 ID를 보관합니다. 운영 변경은 닉네임이 아닌 서버에서 확인한 UID를 대상으로 백업·조건부 갱신·재조회합니다. 이 기능은 사용자 요청에 따른 특정 기록 수정용이며 강화 진위를 서버에서 보증하지 않습니다.

## 자동 수급 저장 한도

자동 제련과 순위 보너스의 합계는 최고 기록 기준 다음 단계의 보호권 원가와 일반 강화 원가를 합한 3회분까지만 채웁니다. 최소 10,000 별철이며 1,000 단위로 올림합니다. +32는 2,261,000, +100은 85,538,000 별철입니다. 현재 검이 파괴·판매·하락해도 최고 기록 기준 한도는 내려가지 않으며, 최고 기록이 오르면 새 한도를 계산합니다. 할인 시간이나 현재 순위는 한도를 바꾸지 않습니다.

온라인·오프라인 수급 모두 남은 공간만 지급하며 한도에 도달한 뒤의 대기 시간은 저장하지 않습니다. 가득 찬 상태에서 사용하면 그 시각부터 수급을 재개합니다. 기존 한도 초과 잔액을 잘라내지 않으며, 감정가 10%의 무기 판매 대금도 전액 지급합니다. 잔액이 한도보다 적어져야 자동 수급이 다시 시작됩니다. 브라우저 이전 탭이 무제한 수급을 새 진행에 덮어쓰지 못하도록 저장 키를 한 번 옮기되, 강화·효과·보호권·잔액·운영자 수정 이력을 그대로 보존합니다.

## 새 버전 자동 갱신과 이전 클라이언트 제한

클라이언트 버전은 엔진의 `clientRevision`, 공개 `release.json`의 `revision`을 같은 증가 정수로 배포합니다. 진입·1분 주기·화면 복귀·온라인 복귀·마지막 확인 이후 15초가 지난 동작 전에 새 버전을 확인합니다. `cache: no-store`와 임의 조회 파라미터를 쓰고, 새 버전 발견 시 새 강화·판매·보호권·특강·등록을 중단한 뒤 진행 중 저장과 Web Lock을 마치고 저장 결과를 확인하여 새 URL로 갱신합니다. 저장이 실패하면 갱신을 멈추고 재시도 버튼을 표시합니다. 동일 갱신을 두 번 시도해도 구버전이면 자동 반복을 멈춰 CDN 전파 중 무한 갱신을 방지합니다. 연결 확인 실패 시 로컬 플레이는 허용하고 재연결 시 다시 확인합니다.

서버 랭킹 생성·갱신은 `rulesVersion: forge-sync-1`을 요구합니다. 이전 기록의 조회와 본인 삭제는 유지하며, 같은 점수의 이름 변경에서도 새 클라이언트는 현재 프로토콜을 포함합니다. 강화 규칙이 바뀌는 배포에서는 클라이언트의 `rankingProtocol`, 공개 manifest, 서버 허용 값을 함께 변경합니다. 신규 구현 이전부터 계속 열려 있던 옛 탭은 새 갱신 코드를 실행할 수 없으므로 최초 한 번 새로고침이 필요합니다. 그 탭에서 새 고득점 제출은 서버가 거부합니다. 이 버전 표식은 오래된 정상 클라이언트를 차단하는 장치이며, 결과 조작이나 매크로를 판별하는 서버 강화 판정의 대체물이 아닙니다. 기존 공개 무기나 저장을 지우거나 부정 기록으로 단정하지 않습니다.
